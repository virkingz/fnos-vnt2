# VNT 组网（飞牛 fnOS 插件）

把 [vnt-dev/vnt](https://github.com/vnt-dev/vnt) 的 `vnt2_web` 核心封装成飞牛 fnOS 的 `.fpk` 应用。

**这是一个「壳」**：不含任何 vnt 二进制，只负责三件事——设置访问令牌、托管核心进程、在线更新核心。**组网的添加与启停全部交给 vnt2_web 自带网页**。

## 特性

- **安装极简**：向导只问两个端口（均有默认值），其余全部应用内设置
- **核心自动更新**：从 GitHub Releases 按架构拉取，带进度、失败自动回滚
- **手动上传兜底**：网络不通时自行下载核心上传安装
- **网络代理**：支持 SOCKS5 / SOCKS5H / SOCKS4 / HTTP / HTTPS
- **令牌自动登录**：打开组网面板自动带令牌，无需手工粘贴
- **原生应用形态**：组网面板内嵌在管理页，地址栏保持飞牛域名
- **一个桌面图标**：所有操作都在「VNT 组网」里完成
- **一个包通吃 x86_64 与 ARM**：二进制在运行时按架构下载
- **升级不丢核心**：已下载的核心与配置不受 fpk 升级影响

## 下载

到 [Releases](../../releases) 下载最新的 `vnt-nas.fpk`。

## 分工

| 谁 | 负责什么 |
|----|----------|
| **本插件** | 安装；设置访问令牌、端口、下载源；启动/停止核心；检查并更新核心；查看日志 |
| **vnt2_web 网页** | 添加组网、填组网编号/服务端/密码、启动组网、查看节点与路由 |

## 安装

飞牛桌面 → 应用中心 → 右上角菜单 → 安装本地应用 → 选择 `vnt-nas.fpk`。

或命令行：

```bash
appcenter-cli install-fpk vnt-nas.fpk
```

**安装时填两个端口**（都有默认值，通常直接下一步即可）：

| 端口 | 默认 | 用途 |
|------|------|------|
| 管理页端口 | 19099 | 打开「VNT 组网」时访问的端口 |
| 组网面板端口 | 19199 | vnt2_web 自带组网页面所用端口 |

其余全部在应用内部设置：

- 访问令牌 —— 安装时自动随机生成，可在管理页「访问设置」里改
- 下载源（镜像）与网络代理 —— 在「访问设置」里填
- 组网参数 —— 在「组网面板」里填

安装过程**不下载任何二进制**，所以装得很快，也不受网络影响。

## 使用（四步）

**第一步：下载核心**

从飞牛桌面点「VNT 组网」打开管理页 → 「核心更新」标签 → 点「检查更新」。
确认显示的版本可下载后，点「下载核心」，进度条走完即完成。

> 首次进入时主按钮就是「下载核心」。下载源不可用时，先到「访问设置」填镜像前缀。

**第二步：设置访问令牌（可选）**

「访问设置」→ 「访问令牌」→ 可点「随机生成」再保存。
安装时已自动生成过一个，不改也能用。

**第三步：启动核心**

「核心更新」→ 点「启动核心」，状态变为「核心运行中」。

**第四步：组网**

「组网面板」→ 点「打开组网面板」在浏览器中打开（会自动带上令牌，无需手工登录）。
在面板中新建组网配置，填写：

- **组网编号**：标识虚拟网络，如 `123456`
- **服务端地址**：`vnt2.rustvnt.com:29872`（公共）或自建服务端
- **组网密码**：建议填写，节点间端到端加密

所有需要互联的设备填**相同**的这三项，启动后即组成虚拟局域网。

## 端口与访问方式

安装时设置两个端口（都有默认值）：

| 端口 | 默认 | 用途 |
|------|------|------|
| 管理页端口 | 19099 | 核心更新、访问设置、日志 |
| 组网面板端口 | 19199 | vnt2_web 自带的组网界面 |

### 为什么是两个端口

管理页与组网面板各占一个端口，用途不同，也都可配置以避免与其它应用冲突。

**组网面板经本应用反向代理**（挂在管理页的 `/core/` 下），因此：

- 与飞牛桌面**同源**，可直接 iframe 内嵌，不受浏览器混合内容策略限制
- 地址栏保持飞牛的 `:5666/app/vnt-nas`，形如原生应用
- 访问令牌由代理注入，**页面内无需手工粘贴**

### 代理是怎么做到不改坏二进制的

vnt2_web 把前端资源编译在 ELF 二进制内部，因此**不能**直接对二进制做替换。
本应用只改写 **HTTP 响应里的纯文本**，并遵循两条规则：

1. **只改写 HTML 中的 `/assets/...`** 绝对路径（改成带 `/core/` 前缀）
2. **完全不碰 JS** —— 改由注入 vnt2_web 官方预留的 API 接管钩子
   `__VNT_API_REQUEST__`，由宿主（本应用）代为拼出正确地址并附令牌

另外必须注入 `<base href=".../core/">`：vnt2_web 用 Vue Router 的
`createWebHistory()`，它在未显式传 base 时会读取 `<base>`，
不注入则路由匹配不到条目、页面空白。

### 组网面板的监听范围

「访问设置」→「组网面板监听范围」：

| 选项 | 效果 |
|------|------|
| **全部网卡**（默认） | 局域网内其它设备也能用 `http://NAS:19199` 直连面板 |
| **仅本机** | 只有飞牛本机可访问该端口（内嵌不受影响） |

> 面板走 `/core/` 内嵌时不受此设置影响；它主要决定 19199 是否对外可达，
> 便于排查问题时直连验证。
从其它设备点该图标会连不上。

### 令牌自动登录

面板经本应用代理，令牌由代理注入，**打开即用，无需手工粘贴**。
界面上的「面板地址」展示的是不含令牌的版本，避免令牌出现在页面上。

### 面板打不开时

「组网面板」页内置「**自检面板可用性**」按钮，逐项给出结论，
并附一段**由浏览器亲自实测**的结果（服务端自检通过 ≠ 浏览器取得到）：

```
[正常] 核心已下载       —— 核心二进制存在
[正常] 访问令牌已设置   —— 令牌已就绪
[正常] 核心正在运行     —— 核心进程在运行
[正常] 核心端口可连接   —— 127.0.0.1:19199 可连接
[正常] 组网面板可访问   —— 面板首页可访问（1300 字节）
[正常] 内嵌代理链路      —— 代理页面可访问（1495 字节），资源路径已改写
```


## 桌面入口

安装后飞牛桌面上只有一个图标：

| 图标 | 内容 |
|------|------|
| VNT 组网 | 管理页（核心更新 / 访问设置 / 组网面板 / 日志） |

**组网面板就在管理页的「组网面板」标签里直接内嵌显示**，
并附带「在新窗口打开」「重新加载」「复制面板地址」等辅助操作。

## 核心更新

vnt 官方发版频繁。管理页「核心更新」标签：

1. 点「检查更新」→ 显示当前版本与最新版本，并给出建议动作
2. 按提示点「下载核心」或「更新到 vx.y.z」

更新失败会**自动回滚**到上一个版本，不会把环境弄坏。

### 手动上传核心

网络不通、镜像没同步某个版本，或想指定版本时，用同页的「手动上传核心」：

1. 从 [Releases](https://github.com/vnt-dev/vnt/releases) 下载对应架构的
   `vnt2-<架构>-unknown-linux-musl-v<版本>.zip`
2. 在该区域选择文件 → 点「上传并安装」

版本号会自动识别（文件名或程序自身），也可手动填写。
也支持直接上传解压出来的 `vnt2_web` 文件。

上传会做校验并给出明确提示：

| 情况 | 提示 |
|------|------|
| 上传 Windows 程序 | 这是 Windows 程序，当前系统需要 Linux 版本 |
| zip 里没有 vnt2_web | 压缩包内未找到 vnt2_web |
| 文件太小 / 不是程序 | 不像是核心程序，请上传对应压缩包或二进制 |

安装流程与在线下载完全一致（停核心 → 备份 → 原子替换 → 重启 → 失败回滚）。

### 版本号查询的可靠性

按以下顺序尝试，取到后都做严格校验（只接受 `数字.数字[.数字]` 形态）：

1. `latest.json` —— vnt 官方随每个 release 发布的版本清单，最可靠且镜像可代理
2. `releases/latest` 的 302 重定向
3. GitHub API

> 早期版本直接按 `/` 切分重定向地址取末段，遇到镜像把整段 URL 编码时会得到
> `https%3A%2F%2F...` 这类内容，导致拼出错误下载地址而 404。现已改为先 URL 解码
> 再用正则严格提取。

## 下载源与网络代理

「访问设置」里有**两种互相独立**的出网配置，可只配其一，也可同时使用：

| 配置 | 作用层 | 说明 |
|------|--------|------|
| **镜像前缀** | URL 层 | 把下载地址改写到镜像站，如 `https://ghfast.top` |
| **网络代理** | 网络层 | 让请求经代理隧道出去，适合本机需要代理才能上外网 |

### 网络代理用法

在「访问设置」的「网络代理」填地址后保存，点「测试连通性」可立即验证：

```
socks5h://127.0.0.1:1080     推荐：由代理解析 DNS，穿透性更好
socks5://127.0.0.1:1080      本地解析 DNS
socks4://127.0.0.1:1080
http://127.0.0.1:7890        HTTP/HTTPS 代理
https://proxy.lan:8443
127.0.0.1:7890               省略协议时按 http 处理
```

留空即直连。「测试连通性」会实际访问 GitHub 并报告耗时，成功即证明整条链路可用。

> **实现说明**：Python 标准库的 `urllib` 不支持 SOCKS5，因此配置代理后所有出网请求
> （版本查询、核心下载、安装脚本里的 curl）统一走 `curl`，它原生支持
> socks5/socks5h/http。未配置代理时仍用 `urllib`，不额外启动进程。
> 若使用 SOCKS 代理但系统没有 curl，界面会提示这一点。

## 为什么做成壳

把二进制打进 fpk 意味着每次 vnt 发版都要重新打包分发。做成壳之后：

- 核心下载到 `var/bin/`，**升级插件不会覆盖它**
- vnt 发新版时，管理页点一下即可，不用重装 fpk
- 一个 fpk 通吃 x86 与 ARM（二进制在运行时按架构下载）

## 运行时数据（升级 fpk 不丢）

```
$TRIM_PKGVAR/            # /vol{n}/@appdata/vnt-nas
├── bin/
│   ├── vnt2_web          # 核心（在线更新，不属于 fpk）
│   ├── webtoken          # 访问令牌（0600）
│   └── .vnt_version      # 当前核心版本
├── vnt_config/           # vnt2_web 自己管理的组网配置
│   └── *.toml
├── cache/                # 下载缓存 + vnt2_web.bak 回滚备份
├── log/                  # main / update / shell / vnt2_web 日志
└── ports.env             # PANEL_PORT 与内部 VNT_WEB_PORT
```

### 日志会一直增长吗

不会。单个日志超过 **512 KB** 时自动截断，只保留最近 **256 KB**
（保留尾部而非清空，方便回看出事前的现场）。

用「原地截断」而不是「改名轮转」，是因为 `shell.log`（后端进程）与
`vnt2_web.log`（核心进程）是由**外部进程以追加方式持有文件句柄**写入的；
改名会让它们继续写旧文件，轮转等于失效。原地截断对追加写入是安全的。

触发时机：每次写入后顺带检查（开销可忽略），另有每 10 秒一次的巡检
兜底覆盖外部进程写入的日志；服务启动时也会清一次。

「日志」页会显示当前大小与上限，并提供**清空**按钮（需管理员）。

## 打包与测试

```bash
bash scripts/pack.sh            # 产出 vnt-nas.fpk
bash scripts/pack.sh 1.0.1      # 指定版本

python scripts/test_update.py   # 更新机制（34 项，本地模拟，不联网）
python scripts/test_rewrite.py  # 路径改写（16 项）
python scripts/test_mount.py    # 挂载点与端口模型（18 项）
python scripts/test_upload.py   # 版本解析与手动上传（33 项）
python scripts/test_proxy.py    # 网络代理（62 项）
python scripts/test_embed.py       # 桌面入口与双端口（73 项）
python scripts/test_panel_proxy.py # 面板反代与内嵌（23 项）
```

> **Windows 打包注意**：官方 `fnpack` 会把 `cmd/*` 权限打成 `666`，飞牛可能因脚本不可执行而失败。`pack.sh` 强制设为 `755` 并转 LF，跨平台更稳。

## 权限说明

创建 TUN/TAP 虚拟网卡需要 root，因此 `config/privilege` 使用 `run-as: root`（飞牛上 1Panel、OpenVPN 等同类应用做法一致）。

不想给 root 的替代方案：在组网面板里把网卡模式设为 `no`（不创建网卡，仅端口映射），功能受限但可回避特权要求。

## 排障

| 现象 | 处理 |
|------|------|
| 核心启动失败 | 「日志」标签看 `core` 日志；管理页会明确提示原因（如二进制架构不符） |
| 检查更新报网络错误 | 在「访问设置」填镜像前缀后重试 |
| 更新后组网不通 | 更新失败会自动回滚；备份在 `cache/vnt2_web.bak` |
| 面板打不开 | 确认令牌已设置、核心在运行；监听范围若为「仅本机」，需从管理页跳转 |
| 端口被占用 | 管理页端口默认 19988，组网面板 19099，可在应用设置里改 |
